## Technical Decisions & Rationale

### 1. Header-Based Identity Propagation
**Decision**: Chose `X-Consent-UserId` custom header for passing identity from the client to the proxy.
**Rationale**: Unlike cookies, which can be blocked by browsers or require complex cross-domain configuration, custom headers are reliably propagated by our interceptor and are easier to handle in a headless proxy environment.

### 2. Manual XHR/Beacon Patching
**Decision**: Directly patched the `XMLHttpRequest.prototype` and `navigator.sendBeacon`.
**Rationale**: Since ConsentGuard must work without SDK modification, we must sit at the lowest level of the browser's networking stack. Patching the prototypes ensures that any library (like Mixpanel or GA4) that uses these primitives is automatically rerouted without their knowledge.

### 3. Tsup --onSuccess Orchestration
**Decision**: Updated `packages/server/package.json` to use `--onSuccess "node dist/index.js"`.
**Rationale**: Standard `tsup --watch` only rebuilds files. By adding the success hook, the server automatically restarts in the background whenever a core logic change is made, significantly speeding up the dev-test loop.

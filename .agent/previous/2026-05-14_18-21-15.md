## Technical Decisions & Rationale

### 1. Functional Decoupling of Transformations
**Decision**: Moved transformation logic from a switch statement in `transformer.ts` into individual modules.
**Rationale**: As the number of transformation types (strip, hash, redact, regex, salt) grows, a single file becomes unmanageable. Modularization allows each transformation to have its own unit tests and defensive logic without bloating the core engine.

### 2. Mutation Observer for Late-Loading Scripts
**Decision**: Added `MutationObserver` to monitor `document.documentElement`.
**Rationale**: Modern tracking setups often load scripts asynchronously (GTM, Segment). While our global `fetch/XHR` patches catch the network traffic, the Mutation Observer gives us a hook to inspect the scripts themselves and provide better debugging logs (and future blocking capabilities) for late-loading trackers.

### 3. Esbuild over Terser for Minification
**Decision**: Switched Vite minification from `terser` to `esbuild`.
**Rationale**: `terser` is an optional dependency in Vite 3+ and was missing from the environment. `esbuild` is built-in, significantly faster, and provides sufficient minification for our client-side library.

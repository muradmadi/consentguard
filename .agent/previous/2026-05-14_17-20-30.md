## Technical Decisions & Rationale

### 1. Reverting `workspace:` Protocol
**Decision**: Switched from `"@consentguard/shared": "workspace:*"` to `"@consentguard/shared": "*"`.
**Rationale**: Native `npm` workspaces (unlike Yarn/pnpm) often fail to resolve the `workspace:` prefix depending on the environment. Using the standard `*` syntax ensures the project remains accessible to developers using standard `npm` without requiring external package managers.

### 2. Zod for Schema-First Development
**Decision**: Adopted `Zod` as the primary validation library.
**Rationale**: For a privacy proxy, data integrity is paramount. Zod provides both runtime validation (preventing malformed consent updates) and static TypeScript type safety, reducing the risk of logic errors in the transformation engine.

### 3. Recursive Wildcard Transformer
**Decision**: Implemented a recursive traversal function in `src/engine/transformer.ts` supporting `*` wildcards.
**Rationale**: Analytics payloads (like GA4) often contain nested arrays of events. A flat-path stripper would be insufficient. The recursive approach allows us to define rules like `events.*.params.email` to scrub PII across all events in a single batch request.
